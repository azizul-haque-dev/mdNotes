অবশ্যই। এবার **NestJS-এর Module Imports/Exports** একদম ১৫ বছরের একজন ছাত্রকে বোঝানোর মতো করে বুঝি।

# 🧩 আগে Module কী?

NestJS-এ **Module হলো একটা বাক্স/রুম**, যেখানে related code একসাথে রাখা হয়।

ধরুন আপনার application:

```text
Arabic Master
│
├── Auth
├── Users
├── Lessons
├── Words
└── Payments
```

প্রতিটা feature-এর জন্য আলাদা Module:

```text
AuthModule
UserModule
LessonModule
WordModule
PaymentModule
```

যেমন:

```ts
@Module({
  controllers: [UserController],
  providers: [UserService],
})
export class UserModule {}
```

এখানে `UserModule`-এর ভিতরে:

```text
UserModule
├── UserController
└── UserService
```

---

# 🤔 তাহলে Imports/Exports কেন?

এখানেই আসল বিষয়।

ধরুন:

```text
UserModule
   ↓
UserService
```

আর:

```text
AuthModule
   ↓
AuthService
```

এখন `AuthService`-এর UserService দরকার।

কিন্তু `UserService` তো **UserModule-এর ভিতরে**।

তাহলে AuthModule কীভাবে সেটা পাবে?

এখানে আসে:

```text
exports
   +
imports
```

---

# 📤 `exports` = "আমার এই জিনিসটা বাইরে ব্যবহার করতে পারো"

UserModule:

```ts
@Module({
  providers: [UserService],
  exports: [UserService],
})
export class UserModule {}
```

এখানে:

```ts
exports: [UserService]
```

এর অর্থ:

> "UserModule-এর বাইরে অন্য Module-ও চাইলে UserService ব্যবহার করতে পারবে।"

সহজভাবে:

```text
UserModule
┌──────────────────────┐
│                      │
│   UserService        │
│        │             │
│        ↓             │
│     EXPORT           │
│        │             │
└────────│─────────────┘
         ↓
   বাইরের Module
```

---

# 📥 `imports` = "অন্য Module-এর exported জিনিস আমার দরকার"

এখন AuthModule-এ UserService দরকার।

তাহলে:

```ts
@Module({
  imports: [UserModule],
  providers: [AuthService],
})
export class AuthModule {}
```

এখানে:

```ts
imports: [UserModule]
```

মানে:

> "আমার AuthModule-এর মধ্যে UserModule-এর exported provider ব্যবহার করতে চাই।"

---

# 🧠 পুরো ব্যাপারটা

```text
             UserModule
          ┌──────────────┐
          │ UserService  │
          │              │
          │   exports    │
          └──────┬───────┘
                 │
                 │
                 ↓
             AuthModule
          ┌──────────────┐
          │   imports    │
          │              │
          │ AuthService  │
          └──────────────┘
```

অর্থাৎ:

```text
UserModule
    │
    │ export UserService
    ↓
AuthModule
    │
    │ import UserModule
    ↓
AuthService can use UserService
```

# 🧑‍💻 পুরো Code দেখি

### `user.service.ts`

```ts
@Injectable()
export class UserService {
  findUser() {
    return {
      id: 1,
      name: "Rahim",
    };
  }
}
```

### `user.module.ts`

```ts
@Module({
  providers: [UserService],
  exports: [UserService],
})
export class UserModule {}
```

খেয়াল করুন:

```ts
providers: [UserService]
```

মানে:

> UserService এই Module-এর provider।

আর:

```ts
exports: [UserService]
```

মানে:

> UserService অন্য Module-কে ব্যবহার করতে দিচ্ছি।

---

# এবার AuthModule

```ts
@Module({
  imports: [UserModule],
  providers: [AuthService],
})
export class AuthModule {}
```

এখন `AuthService`:

```ts
@Injectable()
export class AuthService {
  constructor(
    private readonly userService: UserService,
  ) {}

  login() {
    return this.userService.findUser();
  }
}
```

NestJS বুঝবে:

```text
AuthService
     ↓
চায় UserService
     ↓
AuthModule
     ↓
imports: UserModule
     ↓
UserModule exported UserService
     ↓
✅ পাওয়া গেছে
```

# ❌ `exports` না করলে কী হবে?

ধরুন আপনি লিখলেন:

```ts
@Module({
  providers: [UserService],
})
export class UserModule {}
```

কিন্তু:

```ts
exports: [UserService]
```

দিলেন না।

তারপর AuthModule:

```ts
@Module({
  imports: [UserModule],
  providers: [AuthService],
})
export class AuthModule {}
```

এখন `AuthService` যদি চায়:

```ts
constructor(
  private readonly userService: UserService,
) {}
```

NestJS বলবে:

> ❌ আমি UserService পাচ্ছি না।

কারণ UserModule বলেই দেয়নি:

> "এই Service বাইরে ব্যবহার করতে পারবে।"

---

# ❌ শুধু `exports` করলেই হবে?

না।

এটাও খুব গুরুত্বপূর্ণ।

UserModule:

```ts
@Module({
  providers: [UserService],
  exports: [UserService],
})
export class UserModule {}
```

এখন AuthModule-এ যদি:

```ts
@Module({
  providers: [AuthService],
})
export class AuthModule {}
```

লিখেন, তাহলে হবে না।

কারণ AuthModule-কে UserModule **import** করতে হবে।

```ts
@Module({
  imports: [UserModule],
  providers: [AuthService],
})
export class AuthModule {}
```

তাই মনে রাখবেন:

```text
Module A
   │
   │ exports
   ↓
Provider বাইরে দিল
   │
   ↓
Module B
   │
   │ imports
   ↓
Provider ব্যবহার করতে পারবে
```

# 🏠 একটা বাস্তব জীবনের উদাহরণ

ভাবুন আপনার একটা স্কুল আছে।

```text
School
│
├── Math Room
└── English Room
```

Math Room-এর ভিতরে:

```text
Calculator
```

এখন English Room-এর ছাত্র Calculator ব্যবহার করতে চায়।

Math Room বলল:

> "Calculator বাইরে ব্যবহার করতে পারবে।"

এটা হলো:

```ts
exports: [Calculator]
```

English Room বলল:

> "আমি Math Room-এর জিনিস ব্যবহার করতে চাই।"

এটা হলো:

```ts
imports: [MathModule]
```

তাই:

```text
exports = বাইরে দেওয়ার permission

imports = অন্য Module থেকে নেওয়ার permission
```

---

# ⭐ খুব গুরুত্বপূর্ণ Rule

একটা জিনিস মনে রাখবেন:

> **Provider যে Module-এ তৈরি হয়েছে, সেই Module-ই decide করে provider বাইরে যাবে কিনা।**

উদাহরণ:

```ts
@Module({
  providers: [UserService],
  exports: [UserService],
})
export class UserModule {}
```

এখানে `UserModule` বলছে:

```text
UserService → Public
```

কিন্তু:

```ts
@Module({
  providers: [PasswordHasher],
})
export class UserModule {}
```

এখানে `PasswordHasher` export করা হয়নি।

তাই:

```text
PasswordHasher → Private
```

অর্থাৎ Module-এর ভিতরে থাকা সবকিছু automatically অন্য Module দেখতে পায় না।

# 🔥 Production Application-এ এটা কেমন হয়?

আপনার Authentication system ধরুন:

```text
AuthModule
│
├── AuthController
├── AuthService
└── TokenService

UserModule
│
├── UserController
└── UserService
```

AuthService-এর UserService দরকার:

```text
AuthModule
      │
      │ imports
      ↓
UserModule
      │
      │ exports
      ↓
UserService
```

Code:

```ts
// user.module.ts

@Module({
  providers: [UserService],
  exports: [UserService],
})
export class UserModule {}
```

তারপর:

```ts
// auth.module.ts

@Module({
  imports: [UserModule],
  providers: [AuthService],
})
export class AuthModule {}
```

এটা NestJS application-এর খুব common pattern।

# 🧠 আরেকটা গুরুত্বপূর্ণ বিষয়

`imports`-এ **Module** দেওয়া হয়:

```ts
imports: [UserModule]
```

`providers`-এ **Provider/Service** দেওয়া হয়:

```ts
providers: [AuthService]
```

`exports`-এ **যে provider বাইরে দিতে চান** সেটা দেওয়া হয়:

```ts
exports: [UserService]
```

অর্থাৎ:

```text
imports  → Module
providers → Service / Provider
exports → Provider / Module
```

---

# 🎯 এক লাইনে পুরো বিষয়

```text
@Module({
  imports: [UserModule],
  providers: [AuthService],
  exports: [AuthService],
})
```

এর মানে:

```text
imports
↓
অন্য Module থেকে জিনিস আনছি

providers
↓
আমার Module-এর নিজের dependency তৈরি করছি

exports
↓
আমার Module-এর জিনিস অন্য Module-কে ব্যবহার করতে দিচ্ছি
```

### মনে রাখার shortcut:

> 📥 **Imports = আনো**
> 📤 **Exports = দাও**
> ⚙️ **Providers = তৈরি/Manage করো**

এটাই Module `imports/exports`-এর মূল concept।
