অবশ্যই। এবার **NestJS Global Modules** একদম ১৫ বছরের একজন ছাত্রকে বোঝানোর মতো করে বুঝি।

# 🌍 Global Module কী?

আগের lesson-এ আমরা দেখেছি:

```text
UserModule
     ↓ exports
UserService
     ↓
AuthModule imports UserModule
```

অর্থাৎ কোনো Module-এর provider ব্যবহার করতে হলে সাধারণত সেই Module-কে `imports` করতে হয়।

কিন্তু কিছু Service আছে যেগুলো **পুরো application-এর অনেক জায়গায় দরকার**।

যেমন:

```text
ConfigService
LoggerService
DatabaseService
```

এগুলোর জন্য বারবার:

```ts
imports: [ConfigModule]
```

লিখতে বিরক্তিকর হতে পারে।

তখন আমরা **Global Module** ব্যবহার করতে পারি।

---

# 🌍 Global Module মানে কী?

সহজ ভাষায়:

> **Global Module হলো এমন Module যেটাকে একবার global করে দিলে application-এর অন্য Module-গুলো সেটার exported provider ব্যবহার করতে পারে, প্রতিবার Module-টাকে `imports` না করেও।**

ধরুন:

```text
             ConfigModule
                  │
             🌍 GLOBAL
                  │
       ┌──────────┼──────────┐
       ↓          ↓          ↓
   AuthModule  UserModule  LessonModule
```

সবাই ConfigModule-এর exported provider ব্যবহার করতে পারবে।

# 🧑‍💻 কীভাবে Global Module বানাবেন?

ধরুন আমাদের `ConfigModule` আছে।

```ts
import { Global, Module } from "@nestjs/common";

@Global()
@Module({
  providers: [ConfigService],
  exports: [ConfigService],
})
export class ConfigModule {}
```

এখানে সবচেয়ে গুরুত্বপূর্ণ:

```ts
@Global()
```

এটা NestJS-কে বলছে:

> "এই Module-এর exported provider পুরো application-এ available থাকবে।"

---

# ⚠️ কিন্তু একটা জিনিস ভুলবেন না

Global Module হলেও provider-কে **export** করতে হবে।

❌ এটা যথেষ্ট নয়:

```ts
@Global()
@Module({
  providers: [ConfigService],
})
export class ConfigModule {}
```

কারণ `ConfigService` export করা হয়নি।

সঠিক:

```ts
@Global()
@Module({
  providers: [ConfigService],
  exports: [ConfigService],
})
export class ConfigModule {}
```

মনে রাখবেন:

```text
@Global()
    +
exports
    =
অন্য Module-গুলো provider ব্যবহার করতে পারবে
```

# 🤔 তাহলে `imports` লাগবে না?

হ্যাঁ—**অন্য Module-এ সাধারণত লাগবে না।**

ধরুন:

```ts
@Global()
@Module({
  providers: [ConfigService],
  exports: [ConfigService],
})
export class ConfigModule {}
```

এখন `AuthModule`:

```ts
@Module({
  providers: [AuthService],
})
export class AuthModule {}
```

এখানে:

```ts
imports: [ConfigModule]
```

দরকার নেই।

তারপর:

```ts
@Injectable()
export class AuthService {
  constructor(
    private readonly configService: ConfigService,
  ) {}
}
```

NestJS `ConfigService` খুঁজে পাবে।

স্কুলের কথা ভাবুন।

কারণ পানি সবার জন্য available।

এটাই Global Module-এর idea।

# 🆚 Normal Module বনাম Global Module

### Normal Module

```ts
@Module({
  providers: [ConfigService],
  exports: [ConfigService],
})
export class ConfigModule {}
```

ব্যবহার করতে:

```ts
@Module({
  imports: [ConfigModule],
})
export class AuthModule {}
```

---

### Global Module

```ts
@Global()
@Module({
  providers: [ConfigService],
  exports: [ConfigService],
})
export class ConfigModule {}
```

AuthModule:

```ts
@Module({
  providers: [AuthService],
})
export class AuthModule {}
```

`ConfigModule` import করতে হচ্ছে না।

# ⭐ কখন Global Module ব্যবহার করবেন?

Global Module **সবকিছুর জন্য ব্যবহার করবেন না**।

এটা সাধারণত এমন dependency-এর জন্য ভালো যেগুলো application-এর প্রায় সব জায়গায় দরকার।

যেমন:

### 1. Configuration

```text
ConfigService
```

প্রায় সব জায়গায় environment variable দরকার হতে পারে।

---

### 2. Logger

```text
LoggerService
```

অনেক Module থেকেই logging করা হতে পারে।

---

### 3. কিছু Core Infrastructure

যেমন application-wide কোনো shared service।

ধরুন আপনার:


আছে।

তাহলে application-এর dependency structure বুঝতে কঠিন হয়ে যাবে।

কোন Module কোন Service ব্যবহার করছে সেটা চোখে দেখে বোঝা কঠিন।

এটা একটা বড় সমস্যা।

# 🚨 Global Module-এর সমস্যা

ধরুন:


এতে architecture পরিষ্কার থাকে।

# 🧠 শেষবারের মতো মনে রাখুন

Normal Module:

```text
Module A
   ↓
export Service
   ↓
Module B
   ↓
import Module A
   ↓
use Service
```

Global Module:

```text
           Global Module
                ↓
       ┌────────┼────────┐
       ↓        ↓        ↓
     Auth      User    Product
       ↓        ↓        ↓
       সবাই exported provider
       ব্যবহার করতে পারে
```

### এক লাইনে:

> **Global Module = এমন Module যার exported provider-গুলো application-এর অন্য Module-এ বারবার `imports` না করেও ব্যবহার করা যায়।**

আর production NestJS-এ সবচেয়ে গুরুত্বপূর্ণ বিষয় হলো: **Global module কম ব্যবহার করুন; explicit `imports/exports` architecture সাধারণত বেশি পরিষ্কার ও maintainable।**
