# Step 2.1 — Backend Auth: Supabase JWT Verification Middleware

> শুধু এই ছোট অংশটা রান করবে। এরপর 2.2-এ MongoDB User sync আসবে।

---

## 1. Supabase Project Setup (যদি এখনো না করে থাকো)

1. https://supabase.com/dashboard → New Project বানাও (region: singapore/mumbai — Bangladesh-এর কাছাকাছি latency-র জন্য)।
2. Dashboard → **Authentication → Providers** এ গিয়ে:
   - Email provider: enable (OTP-এর জন্য "Confirm email" ঠিক করে নাও)
   - Google provider: enable করে Google Cloud Console থেকে Client ID/Secret বসাও
   - Apple provider: পরে iOS-এর সময় করলেই হবে
3. Dashboard → **Settings → Data API → JWT Keys** এ চেক করো signing key asymmetric (ES256) কিনা। না থাকলে "Migrate to new JWT signing keys" অপশন দিয়ে migrate করে নাও — এটা legacy HS256-এর চেয়ে বেশি secure এবং future-proof।
4. Dashboard → **Settings → API** থেকে এই তিনটা কপি করে রাখো:
   - Project URL
   - `anon` public key
   - `service_role` secret key (⚠️ এইটা কখনো mobile app-এ বা git-এ যাবে না, শুধু backend `.env`-এ)

## 2. Backend dependencies install

তোমার existing Step 1 backend project-এর root-এ:

```bash
npm install @supabase/supabase-js
npm install -D @types/node
```

আমরা `jsonwebtoken` বা কোনো manual JWT decode লাইব্রেরি ব্যবহার করছি না — কারণ Supabase-এর নিজস্ব `getClaims()` method JWKS fetching, caching, আর key-rotation সব নিজে handle করে। নিজে সেই লজিক লিখলে সেটা maintenance burden আর security risk দুটোই বাড়ায়।

## 4. Supabase Admin Client

```typescript
// src/config/supabase.ts
import { createClient, SupabaseClient } from '@supabase/supabase-js';

const SUPABASE_URL = process.env.SUPABASE_URL;
const SUPABASE_SERVICE_ROLE_KEY = process.env.SUPABASE_SERVICE_ROLE_KEY;

if (!SUPABASE_URL || !SUPABASE_SERVICE_ROLE_KEY) {
  throw new Error(
    'Missing Supabase environment variables: SUPABASE_URL or SUPABASE_SERVICE_ROLE_KEY',
  );
}

// service_role client — শুধু backend-এর ভেতরে ব্যবহার হবে।
// এই client দিয়ে token verify করা হবে, কোনো user-facing auth call না।
export const supabaseAdmin: SupabaseClient = createClient(SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, {
  auth: {
    autoRefreshToken: false,
    persistSession: false,
  },
});
```

## 6. JWT Verification Middleware

```typescript
// src/features/auth/auth.middleware.ts
import { Response, NextFunction } from 'express';
import { supabaseAdmin } from '../../config/supabase';
import { AuthenticatedRequest } from './auth.types';

export async function requireAuth(
  req: AuthenticatedRequest,
  res: Response,
  next: NextFunction,
): Promise<void> {
  try {
    const authHeader = req.headers.authorization;

    if (!authHeader || !authHeader.startsWith('Bearer ')) {
      res.status(401).json({
        success: false,
        error: { code: 'MISSING_TOKEN', message: 'Authorization token is required' },
      });
      return;
    }

    const token = authHeader.split(' ')[1];

    // getClaims() JWKS caching, key rotation, expiry — সব নিজে handle করে।
    const { data, error } = await supabaseAdmin.auth.getClaims(token);

    if (error || !data) {
      res.status(401).json({
        success: false,
        error: { code: 'INVALID_TOKEN', message: 'Invalid or expired token' },
      });
      return;
    }

    req.user = {
      sub: data.claims.sub,
      email: data.claims.email as string | undefined,
      phone: data.claims.phone as string | undefined,
      role: data.claims.role as string | undefined,
      aud: data.claims.aud as string,
      exp: data.claims.exp as number,
    };

    next();
  } catch (err) {
    res.status(500).json({
      success: false,
      error: { code: 'AUTH_INTERNAL_ERROR', message: 'Authentication check failed' },
    });
  }
}
```

## 8. কীভাবে টেস্ট করবে

Supabase dashboard → **Authentication → Users** এ গিয়ে একটা test user বানাও, অথবা Supabase-এর REST API দিয়ে sign up করে একটা access token নাও:

```bash
curl -X POST 'https://your-project-ref.supabase.co/auth/v1/signup' \
  -H "apikey: YOUR_ANON_KEY" \
  -H "Content-Type: application/json" \
  -d '{"email":"test@example.com","password":"Test1234!"}'
```

Response থেকে `access_token` কপি করে backend টেস্ট করো:

```bash
curl http://localhost:5000/api/v1/auth/whoami \
  -H "Authorization: Bearer PASTE_ACCESS_TOKEN_HERE"
```

Expected result: `{ "success": true, "data": { "userId": "...", "email": "test@example.com" } }`

টোকেন ছাড়া call করলে `401 MISSING_TOKEN` আসা উচিত।

## এই অংশে যা হলো

- Backend আলাদা login logic লেখেনি — শুধু Supabase-এর issue করা token verify করছে (correct separation of concerns)
- Modern asymmetric JWT verification (`getClaims`) — legacy HS256 secret-based approach avoid করা হয়েছে
- `service_role` key শুধু backend `.env`-এ, কখনো client-এ যাবে না
- Proper error response shape (`success/error/code`) যেটা পুরো backend জুড়ে consistent থাকবে
